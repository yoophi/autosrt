# Whisper 출력의 잘못된 UTF-8과 SIGPIPE

2026-10-29 사용자 제공 WAV(`/tmp/autosrt-Fj8hMkNOvc.wav`)와 ggml-tiny 모델, Homebrew whisper.cpp 1.9.5로 조사했다. 영상 ID는 `-Fj8hMkNOvc`이며, 처음 4분으로 재현 범위를 줄였다.

직접 Whisper stdout을 파일에 저장하자 2:38.880 이후 자막에 잘못된 UTF-8 바이트 `eb ec`가 확인됐다. 이는 보고된 오류의 마지막 정상 자막 직후다. JSON에도 동일한 손상이 있었다. 직접 파일 출력은 SIGPIPE 없이 종료했다.

기존 AutoSRT는 `BufRead::lines()`의 UTF-8 해석 오류에서 읽기 스레드를 종료하고 파이프를 닫았다. 이후 자식이 계속 쓰면서 SIGPIPE를 받았다. 잘못된 바이트 뒤에 출력을 계속 쓰는 통합 테스트에서도 정확히 signal 13이 재현됐다. 외부 실행 도구의 출력 수집이나 GPU 실패를 원인으로 볼 필요 없이 애플리케이션 내부에서 재현 가능한 문제다.

수정 내용:

- stdout/stderr를 `read_until`로 바이트 단위로 끝까지 읽는다. 로그 표시 시에만 손상된 바이트를 대체한다.
- Interrupted 읽기는 다시 시도한다.
- 전사 JSON도 바이트로 읽어 손상된 UTF-8을 `�`로 대체하고 경고한다. JSON 구조 검증은 유지한다.
- Warning 이벤트를 TUI 기록 또는 비대화형 stderr로 전달한다. stdout의 SRT 경로 계약은 유지한다.

회귀 테스트는 GPU 재시도 후 stdout/stderr의 잘못된 UTF-8, 후속 대량 출력, 손상된 JSON 문자열과 사용자 경고를 검증한다. 원시 음원과 로그는 저장소에 포함하지 않는다. 대체 문자는 원래 음성을 복원한 것이 아니므로 해당 자막은 수동 검토가 필요하다.

검증 결과: 수집한 실제 stdout/JSON을 재생했을 때 기존 설치본은 사용자 보고와 동일한 마지막 6개 자막을 남기며 SIGPIPE/exit 1로 종료했다. 수정본은 동일 재생에서 경고와 함께 SRT를 생성하고 exit 0으로 종료했다. 원본을 4분 WAV로 잘라 새로 인식한 실행은 기존/수정본 모두 성공했으므로 잘못된 토큰 발생은 입력 길이·인식 결과에 따라 달라진다. 61분 전체 전사를 재완주한 결과로 해석하지 않는다. 전체 31개 테스트, Clippy, release 빌드가 통과했다.
