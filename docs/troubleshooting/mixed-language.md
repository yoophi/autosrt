# 한국어 도입부 뒤 영어 음성에서 반복 자막이 생성되는 경우

2026-10-29, 영상 `SHGxL8DQOxs`의 실제 입력 WAV로 재현했다. 기본 설정은 `lang=ko`, 엔진은 Homebrew whisper.cpp 1.9.5 / ggml 0.28.0, 모델은 공식 ggml-small.bin이었다. 모델 SHA-256은 공식 배포 파일과 일치했다.

## 확인한 원인

30초 지점의 8초 음성을 `ko`로 인식하면 잘못된 한국어가 생성됐다. 같은 음성에 `auto`를 사용하면 영어로 감지되고 “Everything that comes after writing the code…”라는 영어 본문이 인식됐다. 전체 파일은 한국어 도입부 때문에 `auto`도 한국어를 선택했다.

동일한 Homebrew 엔진과 WAV의 앞 70초를 비교했다. GPU 초기화 문제를 분리하기 위해 모두 `-ng`로 실행했다.

| 언어 | 최대 동일 문장 연속 횟수 | 결과 |
| --- | ---: | --- |
| ko | 19 | 잘못된 한국어 반복 |
| auto | 19 | 한국어로 감지되어 동일 증상 |
| en | 1 | 영어 본문 인식, 반복 해소 |

```sh
whisper-cli -m /path/to/ggml-small.bin -f audio.wav -l en -d 70000 -ng -oj -of english
```

`-nfa`만 추가하면 반복 대신 마침표만 남았고, `-mc 0`도 정상 인식에 실패했다. 동일 버전의 bundled ggml CPU 빌드에서도 `ko` 지정 시 잘못된 결과가 발생했다. 따라서 Flash Attention 비활성화, 문맥 제거, 엔진 교체를 해결책으로 적용하지 않았다. 정상 발화의 반복도 가능하므로 반복 횟수만으로 자막을 삭제하지 않는다.

## 사용 방법과 제한

`--language`는 원본 음성의 언어이며 번역 목적 언어가 아니다. 이 영상의 영어 본문은 다음처럼 처리한다.

```sh
autosrt --no-tui 'https://youtu.be/SHGxL8DQOxs' --language en --output ./SHGxL8DQOxs.en.srt
```

한국어 도입부의 정확성은 별도 확인이 필요하다. 두 언어를 모두 정확히 보존하려면 언어 경계에서 나누어 각 언어로 인식하고, 합칠 때 원래 시간 오프셋을 반영해야 한다. 현재 AutoSRT에는 구간별 자동 언어 전환 기능이 없다. 저장된 기본 언어를 바꾸지 않고 명령별 언어 옵션으로 덮어쓸 수 있다.

## 별도 GPU 문제

이 환경(macOS 15.6.1 / M2 Pro)의 ggml Metal 로그에는 bfloat4 변환 함수의 `constexpr` 셰이더 컴파일 오류가 있었다. AutoSRT는 GPU 초기화 실패 후 CPU로 재시도했다. CPU에서 언어를 올바르게 지정하면 영어 본문이 인식되므로 GPU 오류 자체를 반복 자막의 원인으로 볼 수 없다. GPU 드라이버/라이브러리는 이 조사에서 변경하지 않았다.

## 회귀 검증 범위

실제 음성의 언어·인식 품질은 외부 엔진과 모델에 의존하므로 모의 도구 테스트로 해결을 주장하지 않는다. 실제 WAV 비교로 언어 지정 효과를 검증했으며, CLI 통합 테스트는 기존 언어 옵션 우선순위와 no-tui 입출력 계약을 검증한다. 재현 음원과 엔진 빌드 산출물은 저장소에 포함하지 않는다.
